## 5. Архитектура и алгоритмы

### 5.1. Как работает бот от получения вопроса до выдачи ответа

Пайплайн из шести шагов, весь код — в репозитории:

1. **Нормализация.** Приведение текста к нижнему регистру, `ё → е`, очистка
   пунктуации, токенизация, лемматизация `pymorphy3`, извлечение ключевых слов.
   Отдельно срабатывают детерминированные решатели: арифметика, проценты,
   подсчёт букв, даты, последовательности, площадь/периметр, время.

2. **Маршрутизация.** Вопрос относится к одному из маршрутов:
   - решатель (математика/логика) — отвечает точно и мгновенно;
   - защита персоны («ты бот?», «докажи, что человек») — готовая человеческая реакция;
   - поиск по курируемой базе;
   - безопасный фолбэк, если уверенности нет.

3. **Гибридный поиск.** Собственный BM25 с инвертированным индексом
   (без `rank_bm25`) + косинусная близость по векторам собственного
   Siamese bi-encoder. Итоговая ранжирующая оценка:
   `0.55 * BM25 + 0.45 * cosine`, плюс небольшой буст по предсказанному интенту.

4. **Гейт уверенности.** Precision-first: ответ из базы выдаётся только если
   совпало достаточно значимых терминов. Если совпадение слабое — лучше
   человеческое «сходу не скажу», чем уверенная чушь.

5. **Персона и память.** Один персонаж (Мирас, 17 лет, Астана, AITU, первый курс)
   и антиповтор в рамках раунда: бот не повторяет ответы и не использует
   одинаковые зачины.

6. **Humanizer.** Убирает «книжный» стиль, варьирует регистр, добавляет «)»,
   контролирует длину (цель 90–220, жёсткий потолок 300), считает человеческую
   паузу печати. Для сцены пауза 2–9 секунд, время ядра показывается отдельно.

**Гарантия непустого ответа.** Три уровня фолбэка и финальная `PANIC`-фраза.
За 400 тестовых вопросов (300 red-team + 100 holdout) — **0 пустых ответов**.

### 5.2. Используемые методы

- собственный BM25 (инвертированный индекс, IDF, k1/b);
- собственный BPE-токенизатор, обученный с нуля на корпусе;
- классификатор интентов: BiLSTM + attention pooling (PyTorch, с нуля);
- Siamese bi-encoder: общий BiLSTM, mean+max pooling, 128-мерный L2-нормированный
  вектор, контрастивная функция InfoNCE с in-batch негативами;
- детерминированные решатели на регулярных выражениях и безопасном AST-eval;
- композер фраз и человеческие фолбэки;
- персона, память раунда, humanizer.

Гибридный подход: нейросети + поиск + правила + шаблоны. Ни один компонент
не является готовой языковой моделью.

### 5.3. Модели и происхождение весов

**Предобученные веса не используются.** Ни одной скачанной модели, ни одного
API-вызова, ни `transformers`, ни `sentence-transformers`, ни `word2vec`.

| Компонент | Архитектура | Как получен |
|---|---|---|
| Токенизатор | BPE, 2 000 слияний | обучен с нуля на корпусе проекта |
| IntentClassifier | BiLSTM (2 слоя) + attention | обучен с нуля, 2 693 размеченных примера |
| Bi-encoder | Siamese BiLSTM, 128-d | обучен с нуля, 3 746 контрастивных пар |
| BM25 | инвертированный индекс | собственная реализация |

Артефакты: `vocab.json`, `intent_model.pt`, `bi_encoder.pt`, `bm25.pkl`,
`corpus.jsonl`, `corpus_vectors.npy`, `training_metrics.json`.
Скрипт обучения: `scripts/train.py`. Метрики: `artifacts/training_metrics.json`.

**Текущие метрики (seed-прогон):**

| Метрика | Значение |
|---|---|
| Курируемая база | 1 142 записи / 2 403 формулировки |
| Intent accuracy (val) | 0.733 |
| Contrastive loss | 0.694 |
| Paraphrase Recall@1 / @5 | 0.832 / 0.929 (113 запросов) |
| p50 / p95 latency | 1.0 / 1.7 мс |
| Пустых ответов | 0 |
| Red-team 300 (regression) | 70.7% автоответов |
| Holdout 100 (unseen) | 64.0% автоответов, остальное — человеческие фолбэки |

> Red-team 300 использовался как диагностический набор для поиска пробелов;
> после доработки часть его вопросов пересекается с базой, поэтому основная
> честная метрика — отдельный `holdout_100` (не использовался при разработке).
> Низкое покрытие не равно пустому ответу: бот отвечает человеческим
> «не знаю» и встречным вопросом, что для теста Тьюринга часто убедительнее
> уверенной ошибки.

## 6. Данные и программные зависимости

### 6.1. Используемые данные

| Источник | Назначение | Лицензия |
|---|---|---|
| Авторский курируемый корпус `data/src/*.txt` → `data/kb_*_qa.jsonl` | основные ответы, голос, контрольные вопросы | авторский |
| Авторский `data/curated_qa.jsonl` | ядро базы, персона, ловушки | авторский |
| `Den4ikAI/russian_dialogues` (Hugging Face) | **только** обучение bi-encoder, не выдача ответов | MIT |
| SberQuAD | не используется | — |

Сырые диалоги проходят фильтр: длина, доля кириллицы, отсутствие ссылок,
почты, личных данных и мата; ответы-вопросы отбрасываются. Они **никогда
не выдаются как ответы** — только учат векторное представление.

Данные, сгенерированные чужими LLM, не используются.

### 6.2. Библиотеки и фреймворки

| Библиотека | Версия | Назначение |
|---|---|---|
| Python | 3.12.16 | рантайм |
| numpy | ≥2.0 | векторы, индекс |
| pymorphy3 | ≥2.0 | морфологический словарь (не модель) |
| torch | ≥2.4 | обучение собственных сетей, dense-режим |
| huggingface-hub | ≥0.30 | выгрузка артефактов (не рантайм) |

`transformers`, `sentence-transformers`, OpenAI/Anthropic API и любые внешние
генераторы **не используются**. Полный список — `requirements.txt` и
`requirements-dense.txt` в репозитории.

## 7. Запуск и работа бота

### 7.1. Инструкция по запуску

```bash
# 1. окружение
python3 -m venv .venv
source .venv/bin/activate

# 2. зависимости (полный гибрид)
pip install -r requirements-dense.txt

# 3. артефакты: либо уже в репозитории, либо скачать с Hugging Face
python scripts/pull_model.py --repo mkstudio/happy-artifacts

# 4. офлайн-проверка (сокеты запрещены)
python scripts/preflight.py

# 5. терминал
python run_cli.py

# 6. локальный веб-интерфейс
python run_ui.py
```

Если `torch` не установлен или артефакты не совпали по размеру с корпусом,
бот автоматически работает в BM25-режиме — это страховка, а не ошибка.

**Полностью офлайн:** после установки зависимостей сеть не нужна. В `run_ui.py`
нет CDN, внешних шрифтов и аналитики. `scripts/preflight.py` подменяет сокет
на исключение и прогоняет 13 вопросов — это доказывает отсутствие сетевых
вызовов.

## Приложение В. Надёжность на сцене

- Ни одного пустого ответа на 400 тестовых вопросах.
- Два независимых режима: BM25-only и BM25+dense; при сбое torch бот не падает.
- Артефакты лежат в репозитории и дублируются на HF и флешке.
- `run_ui.py` — stdlib, без внешних зависимостей; стартует за 1–3 секунды.
- Ответ всегда ≤ 300 символов, проверяется в `_finish`.
